# ModeMux 개발 보고서

## 1. 개요
`ModeMux` (Mode Multiplexer)는 시스템의 제어 모드(Manual, Auto, Failsafe)를 관리하고, 각 모드에 적합한 데이터 소스로부터 제어 명령을 선택하여 출력하는 핵심 제어 컴포넌트입니다.

## 2. 주요 설계 사양
### 2.1. 제어 모드 (SystemMode)
- **MANUAL**: 사용자(조종기 등)로부터 직접 제어 명령을 수신하는 모드.
- **AUTO**: 자율 주행 알고리즘 또는 외부 경로 생성기로부터 제어 명령을 수신하는 모드.
- **FAILSAFE**: 통신 두절 또는 시스템 이상 감지 시 진입하는 안전 모드. (모든 제어 출력을 안전 값으로 고정)

### 2.2. 인터페이스 기반 소스 관리
- `IControlDataSource` 인터페이스를 통해 `ManualSource`와 `AutoSource`를 추상화하여 관리합니다.
- 새로운 제어 소스 추가 시 인터페이스만 구현하면 `ModeMux` 수정 없이 통합이 가능합니다.

## 3. 구현 세부 사항
### 3.1. 안전 로직 (Safety Features)
- **워치독 (Watchdog)**:
  - `WATCHDOG_TIMEOUT_MS` (현재 500ms) 동안 데이터 소스로부터 업데이트가 없을 경우 자동으로 `FAILSAFE` 모드로 전환됩니다.
  - 미래의 타임스탬프나 과거의 중복 데이터가 들어올 경우에 대비한 유효성 검사를 포함합니다.
- **FAILSAFE 락다운 (Lockdown)**:
  - 안전을 위해 `FAILSAFE` 모드 진입 후에는 새로운 데이터가 수신되더라도 자동으로 복구되지 않습니다.
  - 관리자의 명시적인 `setMode()` 호출을 통해서만 제어권 회복이 가능합니다.
- **데이터 정제 (Sanitization)**:
  - `ControlDataValidator`를 사용하여 출력 전 모든 제어 값(Velocity, Rudder, Elevator)의 범위(Clamping)를 제한하고 NaN/Inf 값을 방지합니다.

### 3.2. 스레드 안전성 (Thread Safety)
- `Mailbox<T>` 템플릿 클래스를 사용하여 데이터 소스 업데이트와 제어 루프 간의 Race Condition을 방지합니다.
- `std::mutex` 및 `std::atomic`을 활용하여 데이터의 원자적 접근을 보장합니다.
